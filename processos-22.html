ATIVIDADE PROPOSTA

O que vocês vão resolver

Vocês vão aprender Terraform na prática, em três etapas: primeiro leem um arquivo Terraform simples para identificar suas partes; depois refatoram uma infraestrutura duplicada (dev e prod) em um módulo reutilizável, usando workspaces para separar os ambientes; por fim, conectam uma stack completa (rede, computação, balanceamento e banco) organizada em módulos, decidindo a ordem e as dependências entre eles.

Base: apostila, Capítulo 22 (Infraestrutura como Código com Terraform).

OBJETIVOS

O que vocês vão aprender aqui

  • ✓Compreender a sintaxe básica HCL, providers, resources e o fluxo init → plan → apply.
  • ✓Identificar, num arquivo Terraform, o provider, o recurso, o nome do recurso e o comando de revisão.
  • ✓Refatorar uma infraestrutura duplicada em um módulo reutilizável, com variáveis.
  • ✓Usar workspaces da CLI para manter ambientes (dev/prod) separados a partir do mesmo código.
  • ✓Entender como módulos de uma stack (rede, compute, ALB, banco) se conectam por dependências e outputs.
ENTENDA

Infraestrutura como Código (IaC) com Terraform

Use o diagrama como mapa da atividade: ele mostra a estrutura que as respostas do grupo precisam seguir.

IaC significa descrever a infraestrutura em arquivos de texto — um passo a passo que pode ser executado sempre que necessário, em vez de clicar em telas.

Sem provider, o Terraform não sabe onde criar os recursos. O fluxo init → plan → apply ajuda a revisar antes de executar de verdade.

Um módulo bem escrito é reaproveitado por vários ambientes — cada workspace guarda seu próprio estado, sem duplicar código.

FLUXOGRAMA

Da leitura de um arquivo Terraform à stack completa

O fluxograma mostra a ordem da atividade: ler um arquivo simples (Aula 1), refatorar em módulo e separar ambientes com workspaces (Aula 2), e conectar uma stack completa em módulos (Aula 3).

O Passo 2 usa o mesmo código duplicado mostrado na aba Como fazer (ambientes dev e prod) como ponto de partida para o módulo.

Como ler o fluxograma

  1. 1O Passo 1 é sobre ler o código já dado no slide — provider e resource já estão escritos; a tarefa é identificar cada parte, não escrever código novo.
  2. 2O Passo 2 segue o modelo de módulo da aba Como fazer — criem os arquivos exatamente como no modelo antes de responder às perguntas.
  3. 3O Passo 3 usa o mesmo módulo do Passo 2, só muda o ambiente (workspace) — leiam a expressão condicional do bloco locals com atenção para responder.
  4. 4O Passo 4 pede para pensar em dependência: qual recurso os outros módulos precisam para existir primeiro.
  5. 5O Passo 5 pede para completar as lacunas do fluxo e do main.tf — pensem em qual módulo entrega a informação que o outro módulo usa como entrada.
  6. 6O Passo 6 usa o comando que vocês já conhecem desde a Aula 1 para aplicar as mudanças de verdade, e fecha com a reflexão sobre a stack inteira.

PROCEDIMENTOS

Respondam passo a passo

1
Lendo um arquivo Terraform Observem o exemplo abaixo e respondam às questões a seguir.
provider "aws" { region = "us-east-1" } resource "aws_vpc" "minha_vpc" { cidr_block = "10.0.0.0/16" }
Como pensar: observem cada parte do bloco provider e do bloco resource — tipo, nome e configuração — e revejam o ciclo init/plan/apply na aba Como fazer.
2
Criando um módulo reutilizável Cenário: uma equipe criou duas versões quase iguais da infraestrutura, uma para desenvolvimento (dev) e outra para produção (prod). Isso gera dificuldade de manutenção, risco de erro e repetição.
// Etapa 1 — código atual (duplicado nos dois ambientes) resource "aws_vpc" "main" { cidr_block = "10.0.0.0/16" } resource "aws_subnet" "main" { vpc_id = aws_vpc.main.id cidr_block = "10.0.1.0/24" } // Etapa 2 — crie modules/rede/variables.tf variable "vpc_cidr" {} variable "subnet_cidr" {} // e modules/rede/main.tf resource "aws_vpc" "main" { cidr_block = var.vpc_cidr } resource "aws_subnet" "main" { vpc_id = aws_vpc.main.id cidr_block = var.subnet_cidr } // Etapa 3 — no main.tf principal, troquem os recursos pelo módulo module "rede" { source = "./modules/rede" vpc_cidr = "10.0.0.0/16" subnet_cidr = "10.0.1.0/24" }
Como pensar: sigam o passo a passo: primeiro identifiquem a repetição no código atual, depois criem os arquivos do módulo exatamente como no modelo, e por fim troquem os recursos do main.tf pela chamada ao módulo.
3
Workspaces para dev e prod Agora vocês vão usar o mesmo módulo para dois ambientes diferentes, sem duplicar código.
// Etapa 4 — crie os workspaces terraform workspace new dev terraform workspace new prod terraform workspace select dev // Etapa 5 — comportamento por ambiente locals { instance_type = terraform.workspace == "prod" ? "t3.small" : "t2.micro" }
Como pensar: leiam a expressão condicional do bloco locals com atenção — ela decide o tipo de instância de acordo com o workspace ativo no momento.
4
Entendendo a arquitetura da stack Cenário: uma empresa precisa subir uma aplicação com rede, balanceamento, computação e banco. Parte da infraestrutura já está organizada nos módulos rede, compute, alb e banco. O trabalho de vocês é entender e conectar essa stack.
Como pensar: pensem em qual desses quatro recursos os outros precisam para existir — sem ele, os demais não têm onde rodar.
5
Conectando os módulos no main.tf
module "rede" { source = "./modules/rede" } module "compute" { source = "./modules/compute" subnet_id = __________ } module "alb" { source = "./modules/alb" target = __________ }
Como pensar: cada módulo recebe, como entrada, uma saída (output) de outro módulo que já existe — pensem em quem depende de quem antes de preencher as lacunas.
6
Execução e reflexão final
Como pensar: pensem no comando que vocês já usam desde a Aula 1 para aplicar de fato as mudanças.
